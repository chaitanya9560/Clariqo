# PDF citation display and reference selection

Previously PDF chat returned every retrieved passage as an answer source, and the model could place raw strings such as `【file.pdf | page 1】` in displayed text.

PDF chat now asks Groq for a strict JSON object containing Markdown `answer` and `sourceIndices`. Excerpts receive numbered indexes in the request. The server validates every returned index against the current supplied context, requires references for supported PDF answers, maps only selected indexes to file/page pairs and removes duplicate pages. Unsupported excerpts use an explicit empty-reference refusal, retaining existing PDF-only refusal/general-chat fallback behavior. Missing/malformed/out-of-range references fail with an honest retry message rather than showing every retrieved page as a source.

New PDF replies carry `citationVersion: 1`, which persists with saved messages. The chat labels their reference chips **Cited PDF pages**. Standard raw bracketed PDF file/page markers are removed outside fenced/inline code; if a new reply's raw marker conflicts with its structured references, the reply is rejected. Ordinary brackets, maths and code examples stay intact.

Old saved messages remain readable without rewriting account records. Where old bracketed PDF markers match existing stored sources, displayed links narrow to those mentioned pages. If no markers exist, stored chips are explicitly labelled **Retrieved pages for this older answer**. A note explains that the older message predates citation checks. An invented marker does not create a new clickable source. No sources are inferred from filenames alone.

Limits: this checks reference identity, not whether every sentence is supported by the selected passage. The model still chooses references, so source agreement and factual correctness need separate validation. Plain prose references and nonstandard citation syntax are not exhaustively normalised. Older source lists cannot be reconstructed into proven claim-level evidence. Internet citations use their existing separate search-source handling. No full-book or semantic fact-checking claim is made.

Validation: full regression suite 127/127, TypeScript and production build pass. Eighteen new regression cases cover reference selection, duplicate pages, different documents, bad indexes/JSON, missing references, unsupported questions, raw and fabricated citations, code/maths preservation, older messages, persistence, strict schema and API failure/fallback behavior. A real Groq call with synthetic Java notes plus an unrelated History excerpt cited only the Java page. No user PDF content or account records were used in that call. Browser automation remains unavailable, so live signed-in source-button clicks were not repeated.
